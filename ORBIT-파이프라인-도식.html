Problem 01

한 번에 전체 생성

덱 전체를 한 번의 호출로 만들었다. 완료 전까지 화면에는 아무것도 보이지 않았고, 마지막 단계에서 실패하면 처음부터 전부 다시 실행해야 했다.

Solution 01

Stage + Shard 분리

그래서 생성을 9개 stage와 슬라이드 조각으로 나누고, 조각마다 결과를 저장(checkpoint)했다. 이제 실패하면 그 조각만 다시 실행하고, 완성된 슬라이드는 먼저 보여줄 수 있다.

Problem 02

Redis 큐 ≠ DB 상태

그런데 할 일은 Redis 큐에, 진행 상태는 DB에 따로 있었다. 워커가 마지막 재시도 중에 죽으면, DB에는 '실행 중'으로 남지만 처리하는 워커는 없는 작업이 생겼다.

Solution 02

Postgres Queue 통합

그래서 큐 자체를 Postgres 테이블로 옮겼다. 작업 선점, 산출물 저장, 상태 변경이 한 트랜잭션 안에서 끝나므로, 두 기록이 어긋나는 상황 자체가 사라졌다.
